How it works

  1. Inventory counts every element, conref, key, condition, ID and link: the before picture.
  2. Convert swaps reuse for numbered placeholders and runs DITA-OT's Markdown writer.
  3. Restore turns placeholders into MyST includes, substitutions, only blocks and anchors.
  4. Check compares DITA-OT HTML5 with Sphinx for each topic, in each build: text, structure and IDs.
  5. Links checks links, navigation and every old URL offline.

When a topic fails, a Gemini agent proposes a mapping rule. The checks decide whether it works; the agent gets two attempts; a writer approves every rule before it runs again. Approved rules run without the model, so each new kind of element costs one model call, not one per topic.

Economics

Everything scales to zero: a Cloud Run job for migrations, a Cloud Run API, Firestore and Cloud Storage, deployed from GitHub without keys. A migration of the sample map takes about two minutes of compute; the whole product fits in a fifth of Google Cloud's free tier.
